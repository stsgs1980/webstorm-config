# Юникод-политика в не-JS markdown-сниппетах: дизайн

## Проблема

Блок в `eslint.config.js` с `files: ["**/*.md/**"]` (tsParser + unicode-policy) не
работал: эмодзи и псевдографика в сниппетах `json`, `python`, `bash`, `text` проходили
молча, без единого сообщения. Сниппеты `ts`/`js` проверяются отдельным блоком
`**/*.{ts,tsx,js,jsx,mjs,cjs,mts,cts}` и работают.

## Корневая причина

1. Процессор `@eslint/markdown` 8.0.3 извлекает из `*.md` код-блоки только с указанным
   языком: виртуальные файлы вида `<док>.md/<N>_<имя>` (например
   `docs/example.md/3_3.json`). Фенсы без языка и проза не извлекаются вовсе.
2. ESLint линтует виртуальный файл, только если для его пути находится конфиг
   (фильтр `filterCodeBlock`: `configs.getConfig(path) !== undefined`); иначе блок
   пропускается целиком — без правил и без parse-ошибок.
3. В `@eslint/config-array` паттерны, оканчивающиеся на `/*` или `/**` (а также
   одиночная `*`), считаются «универсальными»: файл, который матчится только такими
   паттернами, получает статус `unconfigured` (правило «universal patterns» в
   `getConfigWithStatus`). Поэтому ни `**/*.md/**`, ни `**/*.md/*` сами по себе не
   дают конфиг ни одному сниппету.
4. Выживают только js/ts-сниппеты: их путь дополнительно матчится точечным паттерном
   `**/*.{ts,tsx,js,jsx,mjs,cjs,mts,cts}`.

Проверено эмпирически на текущих версиях (ESLint 9.39, @eslint/markdown 8.0.3):
debug-логи config-array показывают для json-сниппета `Universal files patterns found.
Checking carefully.` и затем `No matching configs found`.

## Решение: единый механизм на любой язык фенса

Заменить мёртвый блок на конструкцию:

```text
{
  files: ["**/*.md/*.*"],
  ignores: ["**/*.md/*.{ts,tsx,js,jsx,mjs,cjs,mts,cts}", "**/*.md/*.md"],
  languageOptions: { parser: <plain-text-parser> },
  linterOptions: { reportUnusedDisableDirectives: false },
  plugins: { "unicode-policy": unicodePolicy },
  rules: {
    "unicode-policy/emoji": "error",
    "unicode-policy/unicode-graphics": "error",
  },
}
```

- `**/*.md/*.*` — точечный (не «универсальный») паттерн, матчит любой сниппет: у всех
  виртуальных файлов процессора есть расширение.
- `ignores` — js/ts-сниппеты остаются за блоком `**/*.{ts,...}` (tsParser и полный
  набор правил не меняются); `markdown`-сниппеты — проза, вне политики.
- Новый файл `eslint-parsers/plain-text.js`: парсер с `parse(text)`, возвращающий
  пустую `Program`. Unicode-правила читают сырой текст через `sourceCode.getText()` —
  AST им не нужна, поэтому любой язык остаётся «валидным» для ESLint.

Рассматривался и отклонён вариант с перечислением конкретных расширений
(`**/*.md/*.json`, `**/*.md/*.py`): фенс `python` создаёт виртуальный файл с
расширением `.python`, и список пришлось бы вести вручную.

## Границы

- Проза (`*.md`-текст) не проверяется: единственная находка по репозиторию — символ
  U+2699 в прозе `docs/webstorm.md` — остаётся допустимой.
- Фенсы без указания языка процессор не извлекает — проверять нечего.
- `markdown`-сниппеты — проза, не линтуются.
- JS/TS-сниппеты — без изменений (tsParser, jsx-a11y, jsdoc и т.д.).
- Без новых зависимостей.

## Проверка дизайна (выполненные зонды)

- Сниппеты `json` / `py` / `python` / `bash` / `text`: эмодзи и псевдографика ловятся
  с верными строками и колонками в `.md`.
- `ts`-сниппет: `@typescript-eslint/no-unused-vars` продолжает срабатывать (tsParser
  активен, регрессии нет).
- Прогон нового конфига по всем `*.md` репозитория: ноль новых сообщений и ноль
  fatal-ошибок — включение покрытия не красит CI.
