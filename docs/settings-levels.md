# Settings уровни: IDE-глобальные, проектные, личные

Памятка отвечает на вопрос «какие настройки живут где» в связке
webstorm-config и WebStorm. Практические шаги - в [webstorm.md](webstorm.md),
машинный runbook - в [webstorm-settings.md](webstorm-settings.md).

## Три уровня

| Уровень        | Где физически                           | На что действует                | Кто главнее        |
| -------------- | --------------------------------------- | ------------------------------- | ------------------ |
| IDE-глобальные | `%APPDATA%\JetBrains\WebStorm<версия>\` | Все проекты без своей настройки | Проект перекрывает |
| Проектные      | `.idea\` внутри репозитория             | Только этот проект              | Всегда выигрывают  |
| Личные         | `.idea\workspace.xml` (не коммитится)   | Этот проект и только у вас      | -                  |

Правило совместимости: глобальное и проектное не конфликтуют - если
проект несёт свою схему или профиль, проектная версия выигрывает.

`<версия>` в путях - каталог установленной версии, например `WebStorm2026.2`;
при обновлении IDE номер меняется, поэтому в документации он не зашит.

## Два смысла слова «шаблонные»

Настройки шаблона webstorm-config делятся на два типа, и это ключ ко
всей путанице:

1. Обычные проектные файлы: содержимое `.idea/` из клона - это и есть
   настройки проекта, ничего импортировать не нужно.
2. «Склад»: часть файлов в репозитории IDE не применяет сама, их
   вручную развозят по машине один раз.

## Что из клона работает сразу, что требует ручного шага

| Настройка               | Файл в репо                  | Из клона               | Развозка по машине    |
| ----------------------- | ---------------------------- | ---------------------- | --------------------- |
| Code Style              | `.idea/codeStyles/`          | [OK]                   | шаг 3: Global         |
| Профиль инспекций       | `.idea/inspectionProfiles/`  | [OK]                   | шаг 4: отдельно       |
| ESLint                  | `.idea/jsLinters/eslint.xml` | [OK]                   | шаг 5: New Projects   |
| Prettier                | `.idea/prettier.xml`         | [OK]                   | шаг 5: New Projects   |
| Словарь                 | `.idea/dictionaries/`        | [OK]                   | шаг 8: Accepted Words |
| Скоупы                  | `.idea/scopes/`              | [OK] путь репозитория  | вручную               |
| Шаблоны файлов          | `.idea/fileTemplates/`       | [OK] «Файл -> Создать» | шаг 2: Copy to IDE    |
| Живые шаблоны           | `.idea/liveTemplates/`       | [FAIL] IDE не читает   | импорт XML, глава 2.3 |
| File Watchers           | нет в репо                   | -                      | шаг 6: вручную        |
| Analyze code на коммите | нет в репо                   | -                      | шаг 7: per-project    |
| EditorConfig и линтеры  | корень репозитория           | [OK]                   | не нужна              |

Детали к таблице: ESLint и Prettier - Automatic плюс fix on save;
шаги нумеруются по главе 3 сводного руководства; скоуп
`generated_changelog` ссылается на путь конкретного репозитория и в
другом проекте инертен; живые шаблоны IDE платформенно не читает из
каталога проекта (тикет IDEABKL-5033), поэтому файлы в репо - «склад»;
EditorConfig и конфиги линтеров - не настройки IDE, их читают любые
инструменты в любом клоне.

## Новый проект: что уже будет на месте

| Сценарий             | Что уже работает                                                                     |
| -------------------- | ------------------------------------------------------------------------------------ |
| Клон webstorm-config | Всё из строк [OK] таблицы выше - это файлы `.idea/`; живые шаблоны - с уровня машины |
| Свежий пустой проект | Только `%APPDATA%`: живые шаблоны. Остальное - дефолты IDE до шагов 3-5              |

Проверка по трём слоям: файлы на диске (агент, сам), поведение открытого
проекта через MCP-инструменты (агент, при открытом IDE), клики в UI
(человек, то, для чего инструмента нет).

Пять контрольных кликов: `rafce` + `Tab` в файле `.tsx`; «Файл ->
Создать -> React Component»; Settings -> Editor -> Code Style - схема
подписана «(Project)»; Settings for New Projects показывает Prettier и
ESLint on save; галочка Analyze code при коммите включена в проекте.

## Пять правил, чтобы не разбирать заново

- `.idea/` из клона = работает сама; глобальная развозка нужна только
  для новых и чужих проектов.
- `%APPDATA%` = уровень машины: живые шаблоны, Global Code Style,
  IDE-профиль, Settings for New Projects, Accepted Words.
- Живые шаблоны - единственная категория, которая из клона не работает
  никогда, только импорт XML (приложение Б.6).
- `.idea/workspace.xml` - личное состояние (галочки, watchers, размеры
  окон); в git не попадает из-за белого списка в `.gitignore`.
- Направление правок: правим в репозитории, реимпортируем в IDE - не
  наоборот. Обратный порядок уже дал расхождение `rafce` (испр. 29.10).
- Агент знает настройки из файлов: проектные (`.idea/`) - гарантированно
  читает и правит; `%APPDATA%` - читает, но правит осознанно (IDE держит
  настройки в памяти, диск перезаписывается только по реимпорту). Живое
  состояние UI агенту недоступно - закрывается кликами человека.

Новый файл в `.idea/` в git не попадёт случайно: `.gitignore` держит
белый список путей; общий файл добавляют в него явно.
